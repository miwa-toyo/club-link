# Club Link — ジュニアクラブ運営アプリ

`clublink_impl_plan.md` に基づく、少年団・ジュニアクラブ向けの運営支援アプリです。
計画書§1の13画面すべて（保護者向け9機能＋管理者向け機能一式）を実装しています。

## 今回の修正（管理者による保護者のパスワード再設定を実装）

FAQに書いていた「パスワードを忘れた場合は管理者が再設定します」を、実際に動く機能として実装しました。

- 管理者一覧（`/admin/admins`、重要管理者限定）の各保護者行に「パスワードを再設定する」ボタンを追加
- 押すと新しい仮パスワードをその場で発行し、**画面に一度だけ表示**する（メール送信の仕組みは無いため、
  管理者がその場でメモしてご本人に伝える運用）
- 再設定すると、旧パスワードでは以後ログインできなくなる
- お問い合わせページのFAQ回答も、実際の操作手順に合わせて更新

## セットアップ

```bash
pip install -r requirements.txt
python run.py
```

`WTForms`のメールアドレス形式チェック（`Email()`バリデータ）が内部で`email_validator`パッケージを
使うため、`requirements.txt`に含めています。既に`pip install -r requirements.txt`を実行済みで
このパッケージだけ足りない場合は、`pip install email_validator`で追加してください。

`http://127.0.0.1:5002/` にアクセスすると、以下が試せます。

- `/register` — クラブ新規作成（作成者が重要管理者になる。同時に「全体」チームを自動作成）
- `/invite` — 招待コードでの参加
- `/login` / `/logout`

登録直後は各種データが空の状態です。動作確認をしたい場合は、管理者ホームの
「🧪 サンプルデータを投入する」から、お知らせ・ルール・FAQ・予定・子供のサンプルを
まとめて投入できます（下記「サンプルデータとプレビュー」参照）。

## 主な画面

- `/me`, `/me/vehicle`, `/me/family`, `/me/family/<id>`, `/me/absences` — マイページ／送迎情報／お子さま管理／欠席連絡
- `/today` — 今日の活動（直近の予定・お知らせをそれぞれ分けて表示）
- `/schedules`, `/schedules/<id>` — 年間予定（月ごと）・詳細（詳細は管理者向けに欠席者一覧を表示）
- `/schedules/<id>/vehicle` — 車出しの自己申告制登録
- `/rules-faq` — ルール・FAQ（カテゴリ選択式で登録、カテゴリ検索対応、印刷ボタン付き）
- `/announcements` — お知らせ（管理者は編集・削除も可能）
- `/accounting/allocations`, `/accounting/fees` — 会計（手動仕訳は一括編集可）・部費（男女別金額に対応）
- `/camps`, `/camps/<id>` — 合宿・合宿費・支出（家計簿式）・持ち物リスト（一括編集・印刷対応）
- `/inventory` — 物品管理（一括編集・削除・追加）
- `/teams` — チーム編成
- `/admin` — 管理者ホーム（招待コード表示、サンプルデータ投入、プレビュー開始、各種管理機能への入口）
- `/admin/admins`, `/admin/year`, `/admin/audit`, `/admin/plan` — 管理者の追加解除・年度更新・監査ログ・契約プラン

## サンプルデータとプレビュー

かつて存在した「デモ専用ログイン」は廃止しました。代わりに、**実際に登録したクラブ**に対して
管理者ホームから次の2つの機能を使うことで動作確認ができます。

1. **🧪 サンプルデータを投入する**（`POST /admin/sample-data`）
   お知らせ3件・ルール2件・FAQ3件・予定2件・子供4名（男女2名ずつ）をそのクラブに投入します。
   既存のデータは削除されず、追加投入されます。
2. **👀 一般保護者としてプレビューする**（`POST /admin/preview/start`）
   セッションに「プレビューモード」フラグを立て、**アプリ全体**（ナビゲーション・すべてのページ）を
   一般保護者から見た状態に切り替えます。管理者専用の項目は表示されなくなり、
   管理者専用ルートへの直接アクセスも403になります（実際の一般保護者と全く同じ制約）。
   常時表示されるバナーの「プレビューを終了する」でいつでも元に戻れます。

この2つを組み合わせることで、実際の登録フローのまま「管理者が入力した内容が、
一般保護者にどう見えるか」を、アカウントを切り替えることなく確認できます。

## レイアウトはスマホ・PCで共通

一般保護者向け・管理者向けを問わず、全画面で同じレイアウト（`page-shell`）を使用しています。
画面幅に応じたレスポンシブ対応（ボタン・入力欄のサイズ調整など）はスマホでの見やすさのために
残していますが、「管理者はPC向けに情報密度を上げる」といった画面幅による構造的な作り分けは
行っていません。

管理者向けの表形式・編集画面には、あわせて検索・絞り込み機能を追加しています。

- **入金状況一覧**：未納／入金済みで絞り込み表示（絞り込みで非表示になった行は、保存しても状態が変わらない安全な設計）
- **管理者一覧**：保護者名で検索
- **監査ログ**：操作種別（`rule_updated`等）で絞り込み

## 権限モデル

| 権限レベル | できること |
|---|---|
| （一般保護者） | 今日の活動・予定・お知らせ・ルール/FAQの閲覧、マイページ、欠席連絡、車出しの申し出 |
| 編集 | 上記に加えて、会計・合宿・物品・部費設定・駐車場管理、各種の追加・編集・削除、サンプルデータ投入・プレビュー開始 |
| 重要管理 | 上記に加えて、管理者の追加・変更・解除、年度更新、監査ログ閲覧、契約プラン変更 |

一般保護者のナビゲーションは今日の活動・予定・お知らせ・ルール/FAQ・マイページ・ログアウトの
最低限の項目のみとし、運営系の項目（会計・合宿・物品・管理者ホーム等）は編集権限以上にのみ表示します
（ページ自体の閲覧権限は変更していません。詳細は「設計判断」参照）。

## 設計判断（計画書からの簡略化点・意図的な逸脱）

1. 車情報は「子供ごと」ではなく「保護者本人」に紐付け（`/me/vehicle` として実装）。
2. `team_bp` は未実装のため、クラブ作成時に「全体」チームを1つだけ自動生成し、
   全ての予定をそのチームに紐づけている。
3. ルール識別子はマニュアルの `<slug>` ではなく `category` 文字列をそのままURLに使用。
4. 車出しは送迎可の保護者が自己申告で登録・取消する方式とした（自動割当ては将来課題）。
5. 部費に途中から参加した保護者分の `Payment`/`CampFee` 自動生成は未対応。
6. `AccountingEntry.source_type` は計画書の3区分ではなく、`CampFee`と`CampExpense`の主キー
   衝突を避けるため「合宿費」「合宿支出」に分割している（二重計上防止のための意図的な逸脱）。
7. 子供は常に1チームのみに所属する運用とした。
8. `SchedulePhoto.schedule_id` は「アップロード→OCR確認→手動で予定作成」というフローに
   対応するためNULL許容とした。OCR結果からの自動予定作成は行わず、テキスト抽出のみ。
9. 一般保護者のナビ簡素化は表示レベルの分離であり、会計・合宿ページ自体の閲覧権限（保護者本人が
   自分の部費・車出し状況を確認する機能）は維持している。

## OCR機能について

`ocr_bp`（写真からのテキスト抽出）はpytesseract/Pillow/tesseract-ocr本体が未インストールの
環境では自動的に空文字にフォールバックし、アプリ全体は正常に動作し続けます（この経路はテスト済み）。
ただし実際のOCR抽出精度そのものは、ネットワーク遮断環境のため検証できていません。
本番投入前に `pip install pytesseract Pillow` と `tesseract-ocr`（+ 日本語データ）の
インストールを行い、動作確認をしてください。
