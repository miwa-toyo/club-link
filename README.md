# Club Link — ジュニアクラブ運営アプリ

少年団・ジュニアクラブ向けの運営支援アプリです。保護者向け9機能と管理者向け機能一式（計画書§1の13画面）を実装しています。

**構成**：Flask + SQLAlchemy / 12ブループリント / 55ルート / 44テンプレート / 13モデル

---

## 起動方法

```bash
pip install -r requirements.txt
python run.py
```

`http://127.0.0.1:5002/` にアクセスします。

| URL | 用途 |
|---|---|
| `/register` | クラブ新規作成（作成者が重要管理者になる。「全体」チームを自動作成） |
| `/invite` | 招待コードで参加 |
| `/login` `/logout` | ログイン・ログアウト |

> `Email()` バリデータが内部で `email_validator` を使うため `requirements.txt` に含めています。既にインストール済みでこれだけ足りない場合は `pip install email_validator` を実行してください。

登録直後はデータが空です。動作確認は下記の「サンプルデータ」を使ってください。

## 主な画面

### 保護者向け

| パス | 内容 |
|---|---|
| `/today` | 今日の活動（直近の予定・お知らせを分けて表示） |
| `/schedules` `/schedules/<id>` | 年間予定（月ごと）・詳細（管理者には欠席者一覧） |
| `/schedules/<id>/vehicle` | 車出しの自己申告制登録 |
| `/rules-faq` | ルール・FAQ（カテゴリ登録、キーワード検索、絞り込み、印刷） |
| `/announcements` | お知らせ（管理者は編集・削除可） |
| `/me` `/me/vehicle` `/me/family` `/me/absences` | マイページ／送迎情報／お子さま管理／欠席連絡 |

### 運営向け（編集権限以上）

| パス | 内容 |
|---|---|
| `/accounting/allocations` `/accounting/fees` | 会計（手動仕訳は一括編集）・部費（男女別金額対応） |
| `/camps` `/camps/<id>` | 合宿・合宿費・支出（家計簿式）・持ち物リスト（一括編集・印刷） |
| `/inventory` | 物品管理（一括編集・削除・追加） |
| `/teams` | チーム編成 |
| `/support` | お問い合わせ窓口・よくある質問（管理者ホームから遷移） |

### 管理者ホーム（重要管理）

| パス | 内容 |
|---|---|
| `/admin` | 招待コード表示、サンプルデータ投入、プレビュー開始、各管理機能への入口 |
| `/admin/admins` | 管理者の追加・変更・解除、保護者パスワードの再設定 |
| `/admin/year` | 年度更新（在籍／卒団／退部の一括設定、OB/OG一覧） |
| `/admin/audit` | 監査ログ（操作種別で絞り込み） |
| `/admin/plan` | 契約プラン（「📊 プランを比較する」で比較表を表示） |

管理者ナビは「管理者ホーム」1つに集約しており、各機能はそこから開きます。

## 権限モデル

| 権限レベル | できること |
|---|---|
| 一般保護者 | 今日の活動・予定・お知らせ・ルール/FAQの閲覧、マイページ、欠席連絡、車出しの申し出 |
| 編集 | 上記に加えて、会計・合宿・物品・部費設定・駐車場管理、各種の追加・編集・削除、サンプルデータ投入・プレビュー開始 |
| 重要管理 | 上記に加えて、管理者の追加・変更・解除、年度更新、監査ログ閲覧、契約プラン変更 |

一般保護者のナビは今日の活動・予定・お知らせ・ルール/FAQ・マイページ・ログアウトのみを表示し、運営系の項目は編集権限以上にのみ出します。ただし**ページ自体の閲覧権限は維持**しており、保護者本人が自分の部費・車出し状況を確認する機能は残しています。

## 動作確認（サンプルデータとプレビュー）

「デモ専用ログイン」は廃止しました。代わりに、**実際に登録したクラブ**に対して管理者ホームから次の2つを使います。

1. **🧪 サンプルデータを投入する**（`POST /admin/sample-data`）
   お知らせ3件・ルール2件・FAQ3件・予定2件・子供4名（男女2名ずつ）を投入します。既存データは削除されず追加されます。
2. **👀 一般保護者としてプレビューする**（`POST /admin/preview/start`）
   アプリ全体（ナビ・全ページ）を一般保護者から見た状態に切り替えます。管理者専用項目は非表示になり、管理者専用ルートへの直接アクセスも403になります。常時表示バナーの「プレビューを終了する」で戻れます。

投入したサンプルデータは、**🗑️ サンプルデータを削除する** で削除できます。サンプル特有の値に完全一致するものだけを対象とするため、自分で追加したデータは消えません。

## 設計判断（計画書からの主な簡略化点）

1. 車情報は「子供ごと」ではなく「保護者本人」に紐付け（`/me/vehicle`）。
2. クラブ作成時に「全体」チームを1つ自動生成し、全予定をそこに紐付け。
3. ルール識別子は `<slug>` ではなく `category` 文字列をそのままURLに使用。
4. 車出しは送迎可の保護者が自己申告で登録・取消する方式（自動割当ては将来課題）。
5. 途中参加の保護者分の `Payment`/`CampFee` 自動生成は未対応。
6. `AccountingEntry.source_type` は「合宿費」「合宿支出」に分割（主キー衝突回避・二重計上防止のための意図的な逸脱）。
7. 子供は常に1チームのみに所属する運用。
8. `SchedulePhoto.schedule_id` は「アップロード→OCR確認→手動で予定作成」のフローに対応するためNULL許容。OCRからの自動予定作成は行わず、テキスト抽出のみ。
9. 一般保護者のナビ簡素化は表示レベルの分離であり、ページの閲覧権限は変更していない。

## レイアウト

全画面で同じレイアウト（`.page-shell`）を使用しています。PCでは画面幅に応じて段階的に最大幅を広げ（1000px以上で1200px、1400px以上で画面幅の90%、1800px以上で最大1600px）、スマホ幅（600px以下）には影響しません。画面幅による構造的な作り分けは行っていません。

管理者向けの表・編集画面には検索・絞り込みを追加しています。

- **入金状況一覧**：未納／入金済みで絞り込み（絞り込みで非表示の行は、保存しても状態が変わらない設計）
- **管理者一覧**：保護者名で検索
- **監査ログ**：操作種別（`rule_updated` 等）で絞り込み

## OCR機能について

`ocr_bp`（写真からのテキスト抽出）は pytesseract / Pillow / tesseract-ocr 本体が未インストールの環境では自動的に空文字にフォールバックし、アプリ全体は正常に動作し続けます。

実際のOCR精度の検証はネットワーク制限環境のため未実施です。本番投入前に `pip install pytesseract Pillow` と `tesseract-ocr`（＋日本語データ `tesseract-ocr-jpn`）のインストールを行い、動作確認してください。

## 本番運用時の設定

`clublink/config.py` は環境変数で上書きできる作りです。本番では**環境変数を設定するだけで反映**されます（コード変更は不要）。

| 環境変数 | 既定値 | 用途 |
|---|---|---|
| `SECRET_KEY` | `dev-secret-key-change-in-production` | セッション署名鍵。**本番では必ず設定** |
| `DATABASE_URL` | `sqlite:///clublink.db` | 接続先データベース |
| `UPLOAD_FOLDER` | `uploads` | アップロード先 |

既定値のまま本番運用するとセッションが保護されないため、`SECRET_KEY` は必ず環境変数で上書きしてください。
